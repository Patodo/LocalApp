# 在线创建应用

在「我的应用」或「应用开发」点击「创建应用」，输入希望实现的功能，并选择自己配置的模型。Agent 先讨论需求，然后提出应用名称和摘要。可以继续对话调整，点击「确认名称并创建」后才安装应用。

确认前，源码和对话保存在服务端草稿中，不出现在应用列表。确认后使用原项目目录和原会话，更新模板名称，安装固定的起始页面，并进入正式应用地址。页面自动以开发者身份继续原会话，无需重新说明需求。

每轮开发对话完成后，平台编译当前源码并显示独立预览。预览有独立的访问凭证和测试数据，不修改已上线应用的数据。可以点击「查看已上线版本」返回正式页面。切换为用户身份也会返回正式页面。

预览只执行编译与包结构检查，不表示完整测试通过，不能直接上线。要发布应用，先点击「检查与构建」，通过全部检查后再点击「上线」。初次创建的固定起始页面也不表示应用功能已开发完成。

接口均从登录身份确定用户：

- `POST /api/development/creations`：指定 `providerId` 开始草稿。
- `GET /api/development/creations/:id`：读取自己的草稿及名称提案。
- 原有项目 Agent 接口继续使用同一 `sessionId`。名称提案工具由 Server 处理，不交给浏览器执行。
- `POST /api/development/creations/:id/confirm`：提交已提出的 `name`，创建并返回应用地址。重复确认不会安装第二个版本。
- 原会话 `agent/run` 使用 `continueCreation: true` 自动继续一次。后续正常发送开发需求。
- 构建请求的 `purpose: "preview"` 仅供预览；默认 `release` 执行完整检查。
