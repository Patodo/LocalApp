## Context

现有 Agent 调度适用于对话，托管应用使用 Named SQL 和平台原语。服务器运维脚本需要独立的进程生命周期和授权边界。

## Goals / Non-Goals

**目标**

- 在统一 Server 内按时区和每日窗口运行受信任的脚本。
- 使用现有账号、API Key 与用户组授权，支持即时移除用户权限。
- 在超时和正常停止时清理运行中的任务，避免单实例任务重叠。

**非目标**

- 应用包上传脚本或前端提交可执行命令。
- 多实例分布式调度、离线补跑和历史日志存储。

## Decisions

- 运维通过绝对路径配置 JSON，保留任务定义、环境变量转发名单和手动触发凭据来源的控制权。启动时验证配置。Server 使用固定参数启动子进程。
- 调度器只检查当前分钟，以时间窗口起点为间隔基准。服务监听后检查，关闭时取消后续检查并尝试停止进程树。
- 管理员可以看到全部任务。普通用户的权限由管理员拥有的非系统组实时决定。手动请求另需任务凭据，因为浏览器会话可以申请用户 API Key。

## Risks / Trade-offs

- 脚本共享 Server 的操作系统账号。运维必须保护配置、脚本和工作目录的写入权。
- 单实例最多保留每项任务的最近一次结果。脚本可写入自己的运维日志。
- 正常关闭可以清理活跃的进程树。脚本应以前台方式执行并等待子进程，强制停止进程或主机崩溃没有补跑保证。
