## Purpose

定义从内部仓库生成、校验并发布可重复公开源码快照的允许清单、敏感内容门禁、构建验证和新历史初始化要求。

## Requirements

### Requirement: 公开源码快照采用允许清单

系统 SHALL 从指定 Git commit 生成公开源码快照，只包含公开清单允许的路径，并排除内部资料、未完成变更、运行数据、凭据和发行二进制。经过敏感内容门禁的历史归档 SHALL 保留。

#### Scenario: 从干净 commit 导出
- **WHEN** 维护者对已提交的 commit 执行公开源码导出
- **THEN** 输出只包含允许清单中的已跟踪文件
- **AND** 输出记录源 commit 和文件内容摘要

#### Scenario: 保留安全的历史归档
- **WHEN** `openspec/changes/archive` 中的历史变更通过敏感内容门禁
- **THEN** 这些历史变更出现在公开源码快照中
- **AND** 外部贡献者可追溯当前规格的设计背景

#### Scenario: 排除内部与运行数据
- **WHEN** 源仓库包含未完成的内部变更、`.superpowers/sdd`、数据库、备份、上传文件或内部运维记录
- **THEN** 这些内容不出现在公开源码快照中

### Requirement: 公开快照执行敏感内容门禁

导出流程 MUST 在发布前检查路径、文件类型、文件大小、凭据模式、内部域名和本机绝对路径；任一禁止项命中时 MUST 失败且不得生成可发布结果。

#### Scenario: 检测到凭据
- **WHEN** 候选快照包含 API Key、私钥、证书私钥或非示例环境密码
- **THEN** 门禁失败并报告文件路径和规则名称
- **AND** 日志不输出完整凭据值

#### Scenario: 检测到发行二进制
- **WHEN** 候选快照包含 ELF、Mach-O、PE、安装包或发行压缩包
- **THEN** 门禁失败并报告对应文件

### Requirement: 公开快照可重复验证

相同 Git commit、导出规则和工具版本 MUST 产生相同文件集合及内容摘要。CI MUST 在快照中重新执行 OpenSpec 严格校验、源码构建和核心测试。

#### Scenario: 重复导出
- **WHEN** 对同一 commit 连续执行两次导出
- **THEN** 两次输出的文件清单和内容摘要一致

#### Scenario: 快照缺少构建所需源码
- **WHEN** 允许清单误排除了构建或测试所需文件
- **THEN** 快照 CI 失败并阻止公开发布

### Requirement: 公开仓库从清理快照初始化

首个 GitHub 公开仓库 SHALL 从通过门禁的快照建立新历史，不得推送当前内部仓库历史。公开源码 SHALL 包含 MIT License、README、当前主规格、开发部署指南、贡献指南、安全报告指南和行为准则。

#### Scenario: 初始化公开仓库
- **WHEN** 维护者发布首个公开源码版本
- **THEN** GitHub 仓库首个提交的文件树等于通过门禁的快照
- **AND** 当前内部仓库的历史和远端保持不变
